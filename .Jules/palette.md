## 2024-05-24 - Accessibility: Explicit Focus Rings and ARIA on Navigation

 **Learning:** In Tailwind CSS UI setups, navigation buttons often lack explicit focus indicators, relying on browser defaults which can be inconsistent or invisible against custom backgrounds. `framer-motion` and custom click handlers can sometimes interfere with standard accessibility patterns. In addition, Vite/PostCSS can throw "ambiguous utility" build errors when encountering complex arbitrary class values like `ease-[cubic-bezier(...)]` if they aren't explicitly scoped or escaped.
 **Action:** Proactively applied `aria-current="page"` conditionally for semantic current-page indication and added a standard, highly visible focus ring combo (`focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2`) to all interactive elements within `SidebarNav` and `BottomNav` components to ensure robust keyboard accessibility. Extracted the complex cubic-bezier timing function into standard CSS to resolve a localized Vite build error preventing local verification.
