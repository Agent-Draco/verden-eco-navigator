## 2025-04-25 - Custom interactive components need explicit focus and stable transitions

**Learning:** When building custom interactive components like `GlassButton` using a simple wrapper (e.g. `motion.button` or `div`), native keyboard accessibility for focus states is often missing by default. Furthermore, using arbitrary complex CSS timing functions directly in Tailwind classes (e.g., `ease-[cubic-bezier(0.23,1,0.32,1)]`) can cause Vite/esbuild compilation issues because it can ambiguously match multiple utilities or be hard for the compiler to parse reliably.
**Action:** Always ensure custom interactive elements explicitly implement `focus-visible` styles (`focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-primary...`) to meet strict accessibility standards. Additionally, prefer predefined CSS utility classes or abstract complex arbitrary functions to a CSS file (`.transition-liquid`) instead of using them directly in Tailwind class lists to prevent build instability.
