## 2024-04-29 - GlassButton Accessibility & Stability Fixes
**Learning:** Custom interactive components, particularly those using Framer Motion like `motion.button` (such as `GlassButton`), often miss critical native interactive states (keyboard focus, disabled visuals) out-of-the-box. Additionally, using complex arbitrary Tailwind timing functions like `ease-[cubic-bezier(0.23,1,0.32,1)]` directly in classnames can lead to ambiguous utility matches during Vite/esbuild compilation, risking build failures.
**Action:** Always ensure that custom button wrappers explicitly include Tailwind's `focus-visible` pseudo-class (e.g., `focus-visible:ring-primary focus-visible:ring-offset-background`) for robust keyboard accessibility, and `disabled` states (e.g., `disabled:opacity-50 disabled:pointer-events-none`). Replace complex arbitrary CSS functions in Tailwind classes with explicitly scoped CSS transition utility classes (like `.transition-liquid`) to ensure build stability and UI consistency.
